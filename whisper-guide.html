YouTube Digest

Local Whisper setup

YouTube Digest reads subtitles from the page first. When a video has no caption track, the extension can transcribe the tab's own audio with Whisper running on your computer. Nothing is uploaded: the audio goes to a small server on 127.0.0.1 that you start yourself.

Check first. Open Settings and press Check connection next to the Whisper fields. If it says "Connected", you are done and can ignore the rest of this page.

How it fits together

1 Capture chrome.tabCapture records the audio of the tab you are watching.
2 Transcribe The recording is POSTed to 127.0.0.1:8000/transcribe, served by whisper/whisper_server.py.
3 Return faster-whisper turns the audio into text on your CPU or GPU, and the panel renders it like any other transcript.

Before you start

  • Python 3.9 or newer, with pip on your PATH.
  • About 1 GB of free disk space for the default model.
  • The extension folder you loaded through Load unpacked.
  • A terminal window. It must stay open while you use the feature.

Install and start the server

Run these from the extension folder, the one containing manifest.json.

1Create a virtual environment

cd path\to\video-digest
python -m venv .venv
.venv\Scripts\activate

macOS or Linux: python3 -m venv .venv && source .venv/bin/activate

2Install dependencies

pip install -r whisper/requirements.txt

3Start the server

python whisper/whisper_server.py --model small

The first transcription downloads the model (about 460 MB for small) and prints progress in this terminal. Later runs reuse the cached copy.

4Point the extension at it

Open Settings, tick Enable local Whisper, keep the URL as http://127.0.0.1:8000, and press Check connection. It should report the model and the response time.

Verify without the extension

curl http://127.0.0.1:8000/health

A running server answers {"status":"ok","model":null}. null only means the model has not been loaded yet; the first transcription loads it.

Which model should I use?

Model Download Feel
tiny ~75 MB Fastest, rough on names and accents. Fine for skimming.
base ~145 MB Still fast, noticeably better than tiny.
small default ~460 MB Good balance of speed and accuracy for most videos.
medium ~1.5 GB More accurate, several times slower on CPU.
large-v3 ~3 GB Best quality, wants a GPU to feel responsive.

Set the same name in Settings → Whisper model and in --model, otherwise the server keeps reloading models.

When it does not work

Symptom What to do
Panel says "Local Whisper is not running" The terminal is closed or the process died. Start it again and press Check connection.
Check connection says HTTP 404 or 200 but unexpected Something else answers on that port. Change the port with --port 8001 and update the URL in Settings.
Port 8000 is already in use Start with --port 8001, then set the same URL in Settings.
Model download stalls behind a firewall Set HF_ENDPOINT=https://hf-mirror.com before starting the server, or use a smaller model.
Transcript is empty The tab was paused, muted, or silent. Play the video with sound and retry.
Only the last minute is recognised By design: capture is limited to 5–120 seconds from the current play position. Native captions are always tried first.
DRM or encrypted streams Their audio cannot be captured by the browser at all.

Privacy and limits

  • Audio is sent only to 127.0.0.1. It does not leave your machine, and no API key is involved.
  • The server writes the recording to a temporary file for the duration of the request and deletes it afterwards.
  • Closing the terminal stops the service. The extension then reports that it is not running instead of failing silently.

本地 Whisper 安装与启动

YouTube Digest 会先读页面自带的字幕。视频没有字幕轨时，扩展可以用 你自己电脑上运行的 Whisper 把当前标签页的声音转成文字。音频不会上传：它只发往你自己启动的 127.0.0.1 本地服务。

先检查一下。打开设置，在 Whisper 那一栏点检查连接。如果显示“已连接”，说明已经装好并启动，下面的步骤都可以跳过。

它是怎么配合插件工作的

1 采集 chrome.tabCapture 录制你正在看的这个标签页的声音。
2 转录 录音被 POST 到 127.0.0.1:8000/transcribe，由 whisper/whisper_server.py 处理。
3 返回 faster-whisper 在你的 CPU / GPU 上把音频转成文字，面板像普通字幕一样渲染。

开始前需要准备

  • Python 3.9 或更高版本，pip 可以在终端里直接调用。
  • 约 1 GB 空闲磁盘空间（默认模型）。
  • 你通过“加载已解压的扩展程序”装上的那个插件文件夹。
  • 一个终端窗口，使用期间必须一直开着。

安装并启动服务

以下命令都在插件文件夹里执行，也就是包含 manifest.json 的那一层。

1创建虚拟环境

cd D:\Project\video-digest
python -m venv .venv
.venv\Scripts\activate

macOS / Linux 用：python3 -m venv .venv && source .venv/bin/activate

2安装依赖

pip install -r whisper/requirements.txt

3启动服务

python whisper/whisper_server.py --model small

第一次转录会自动下载模型（small 约 460 MB），进度就打印在这个终端里。之后会复用缓存，不再下载。

4让插件连上它

打开设置，勾选无原生字幕时启用本地 Whisper 转录，地址保持 http://127.0.0.1:8000，点检查连接。应当显示模型名和响应时间。

不开插件也能验证

curl http://127.0.0.1:8000/health

正常会返回 {"status":"ok","model":null}。这里的 null 只表示模型还没加载，第一次转录时会自动加载。

模型怎么选

模型 下载大小 体感
tiny 约 75 MB 最快，人名和口音容易出错，适合快速扫一遍。
base 约 145 MB 依然很快，比 tiny 明显准一些。
small 默认 约 460 MB 速度和准确率的平衡点，多数视频够用。
medium 约 1.5 GB 更准，纯 CPU 下慢好几倍。
large-v3 约 3 GB 质量最好，想顺畅需要 GPU。

设置 → Whisper 模型 和启动命令里的 --model 要写同一个名字，否则服务会反复重新加载模型。

出问题的时候

现象 怎么处理
面板提示 “Local Whisper is not running” 终端被关掉或进程退出了。重新启动服务，再点检查连接。
检查连接返回 HTTP 404，或有响应但不像 Whisper 这个端口上是别的程序。用 --port 8001 换端口，并把设置里的地址改成一致。
8000 端口被占用 用 --port 8001 启动，然后把设置里的地址同步改掉。
模型下载卡住 启动前设置 HF_ENDPOINT=https://hf-mirror.com，或换更小的模型。
转录结果是空的 标签页当时暂停、静音或没有声音。让视频正常播放出声后重试。
只识别出最后一小段 设计如此：一次只抓当前播放位置之后的 5–120 秒。原生字幕始终优先。
DRM / 加密流 浏览器本身就拿不到这类音轨，无法转写。

隐私与限制

  • 音频只发往 127.0.0.1，不离开本机，也用不到任何 API Key。
  • 服务只在处理请求期间把录音落到临时文件，处理完立即删除。
  • 关掉终端服务就停了。这时插件会明确提示“服务没启动”，而不是默默失败。
